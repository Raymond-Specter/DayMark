# 需求与验收范围

## 产品目标

建立稳定、持久化的「时间规划 + 日历 + 重复任务 + 每日提醒 + 完成记录」框架。用户打开首页即可判断今天要做什么；进入进度视图即可理解目标、项目、里程碑当前阶段。规划内容与系统逻辑完全分离，不预装具体课程、考试、求职或学校规划。

## 第一阶段范围

| 能力 | 验收标准 |
| --- | --- |
| Goal | 可创建、查看、修改和删除；包含名称、说明、起始日期、目标日期、状态、优先级、颜色 |
| Project | 可管理项目并关联 Goal；有起止日期、状态、说明 |
| Milestone | 属于 Project，支持起始日期、截止日期、状态、说明 |
| Task | 支持日期、开始/结束时间、截止时间、预计分钟数、优先级、状态、创建/完成时间、来源 |
| Task 状态 | pending、completed、overdue、rescheduled、cancelled；完成后保留记录，重新打开保留操作历史 |
| Routine | daily、every_n_days、weekly、weekdays、custom；自定义间隔支持天/周；可启停及设起止日期 |
| 重复生成 | 同一 Routine 同一原始日期只生成一次；连续生成水位支持停机补齐；编辑规则不重算历史；手动改动的单次任务不被覆盖 |
| 基础依赖 | Task 可以依赖另一个 Task；Routine 可以依赖另一 Routine 原始日期向前偏移 offset_days 的任务；规则图与实际任务图均拦截自依赖与循环 |
| 日历 | 日/周/月视图；支持任务拖动、调整时间、完成、延期、删除；区分全天与定时安排 |
| Today | 今日日期、待办/完成任务、剩余任务、临近截止、昨日未完成；按时间和用户优先级排序 |
| 逾期处理 | 保留历史事项；提供改到今天、选择日期、取消、保持逾期；不自动重排 |
| 提醒 | 0、10、30、60、1440 分钟前；提醒计划独立存储，具有可替换 provider 边界 |
| 每日回顾 | 按日保存实际分钟数、精力 1–5、笔记、完成/未完成任务快照及项目实际时间分配 |
| 基础统计 | 今日完成、本周完成、完成率、计划/实际小时数、项目时间分布、临近截止 |
| 持久化 | SQLite + Alembic；重启后数据仍存在；提供 JSON 导出和 SQLite 在线备份 |

## 明确规则

- 单用户、本机优先，默认时区为 `Asia/Shanghai`，可在设置中修改。
- 优先级 `1` 为高、`2` 为中、`3` 为低；不使用 AI 排序。
- Goal / Project / Milestone 状态由用户维护；任务完成比例用于展示，不自动完成长期目标。
- 日期/时间以设置时区的本地日程表达；审计和完成时间等瞬间统一为 UTC。
- Task 未排期时允许留在任务库；有开始或结束时间必须有日期。第一版单次 Task 不跨午夜，跨天工作拆为多项。
- 计划时间来自预计时长；实际时间只来自每日回顾记录。未分配到项目的实际分钟单独保留，不按计划比例猜测。
- 删除 Task 为软删除；重复任务实例删除后不会在下一次同步复活。
- 上层 Goal / Project / Milestone 被下层引用时，删除应明确阻止，用户先迁移或移除引用。
- 未完成事项由用户选择下一步，系统仅提示，不删除、不自动改期。
- 默认生成到今天之后 30 天；远期日历可查询，显式生成窗口最多 367 天，不以远期孤立窗口跳过中间日期。
- 暂停后恢复跳过暂停期间尚未生成的日期；已因暂停取消的过去实例不恢复，不自动制造历史欠账。
- 同一任务的同一提醒到期时间已经派发后，仅编辑标题或说明不重复提醒。

## 第一阶段不包含

AI Planner / Replanner、自动长期规划、复杂依赖计算、自动进度预测、多用户协作、Google Calendar 双向同步、OpenAI API 调用、考试或求职专属模块。

浏览器与操作系统对后台执行有限制；本版不承诺网页关闭后的系统通知可靠送达。保留独立提醒服务、持久化提醒和一次性派发入口，为未来外部日历与推送集成准备。
