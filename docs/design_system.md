# DayMark 视觉规范

本规范用于统一 DayMark 的现有页面。核心体验是：打开 Today 后，立刻看清**接下来做什么、今天还有多少事、整体走到了哪一步**。界面应像安静、可靠的工作台，强调内容和操作反馈，减少装饰性卡片与大面积渐变。

## 参考与取舍

| 参考 | 可借鉴的模式 | DayMark 的落点 |
| --- | --- | --- |
| [Linear](https://linear.app/docs/projects) | 清楚的项目层级、进度和里程碑 | 侧栏、目标与项目、阶段条 |
| [Sunsama](https://help.sunsama.com/docs/usage-guides/today-view/) | 今日任务与日程并排的聚焦布局 | Today 主列与右侧时间视图 |
| [Things](https://culturedcode.com/things/) | 轻量任务列表与有目的的状态反馈 | 任务行、完成动作、空状态 |
| [Notion Calendar](https://www.notion.com/product/calendar) | 易扫读的时间网格和日程上下文 | 日/周/月日历 |
| [Raycast AI](https://manual.raycast.com/ai/ai-chat) | 紧凑的会话列表、输入区与工具反馈 | AI Assistant 工作台 |

这些是设计参考，并非要复制产品功能。全站采用深色工作台：低对比度的面板与细分隔线组织信息，文字和关键操作保持清晰。日历参考用户提供的深色周视图图片，借鉴其时间网格与彩色日程块，不复制示例数据或第三方集成。

## 设计令牌

| 用途 | 色值 | 用法 |
| --- | --- | --- |
| 页面底色 | `#111216` | 全站工作区 |
| 面板底色 | `#1C1E23` | 表单、列表、日历、对话 |
| 抬升底色 | `#24262D` | 悬停、选中行、弹出层 |
| 主文字 | `#F3F4F6` | 标题、任务、关键数字 |
| 次文字 | `#A9ADB8` | 描述、元信息；正文需保持可读 |
| 分隔线 | `#34363E` | 列表、网格、面板轮廓 |
| 主强调 | `#ACBCF7` | 主按钮、链接、选中项 |
| 完成 | `#76BCA8` | 完成状态，须同时保留文字/图标语义 |
| 警示 | `#E9B478` | 临近截止日期 |
| 错误 | `#E89292` | 失败、逾期、破坏性操作 |

颜色只做辅助编码：任务状态、优先级和进度还必须有文字或形状提示。整页应只有一个主要强调色；用户自定义项目颜色可以出现在日历事件块中，其他页面以窄色条或小圆点标识。深色主题不等于纯黑大面积填充；面板层级、细线、文字亮度与留白共同建立层次。避免大面积渐变、荧光色和不必要的阴影。

## 排版与空间

- 正文使用 `Segoe UI Variable Text`（拉丁字符）与 `Noto Sans SC`（中文），标题优先 `Segoe UI Variable Display`；未安装时回退到 `Microsoft YaHei UI`、`PingFang SC`、系统无衬线。不要让网页依赖外部字体服务才能正常显示。
- 页面标题：桌面 32–38 px / 700，窄屏 25–30 px；区块标题 18–20 px / 650；任务标题 14–15 px / 600；正文 14 px / 400、行高 1.55；标签及元信息至少 12 px。只有英文眉题使用大写和宽字距，中文不刻意拉开字距。
- 时间、日期、时长、百分比使用等宽数字（`font-variant-numeric: tabular-nums`）；避免数字跳动导致列表对不齐。
- 以 4 px 为基本步长：行内 8–12 px、面板内 20–24 px、面板间 20–24 px、页面边距桌面 32–40 px / 手机 16 px。页面内容最大宽度 1480 px；长段落和 AI 回答另限制到易读行宽。
- 面板圆角 6–8 px，输入框 5–6 px，按钮 5–6 px；阴影只用于浮层、焦点区或悬停提示。相邻列表项优先用细分隔线，不给每行套独立卡片。
- 图标沿用项目中的 Lucide：常规 18–20 px、描边 1.7–1.9；不要混入 emoji 图标。

## 页面映射

| 页面 | 信息顺序与视觉重点 |
| --- | --- |
| 全站导航 | 236 px 深色侧栏；当前页用窄强调线与稍亮底色指示，其他项保持低噪声。顶部栏提供面包屑、日期、通知和快捷操作。 |
| Today | 顶部焦点区展示今天日期、下一项任务与完成进度；其下阶段条展示 Goal → Project → Milestone 的当前阶段。主列按时间列出待办，右列放今日时间安排、临近截止日期与复盘入口。未完成昨日任务独立成区，不能混同于今天已排程任务。 |
| 全部任务 / 重复任务 | 任务行以复选框、标题、时间、项目、优先级为主；完成后的行降低对比，但仍可阅读和重新打开。重复规则用紧凑文字说明，避免整行依赖图标解码。 |
| 目标与项目 | 保留层级路径和当前里程碑；进度数字紧邻进度轨道，项目颜色只作侧边标记。空目标状态突出创建入口。 |
| 日历 | 默认周视图，工具栏保留日/周/月切换。深色时间网格使用细线与清楚的小时刻度，当天与当前时间要突出但不刺眼；事件块保留用户颜色，使用柔和底色、细边和可读文字。拖拽时使用轻透明预览，落点明确。 |
| 数据统计 / 每日复盘 | 指标数值为第一视觉层级，计划与实际使用同一量纲。图表减少装饰色和多层阴影；复盘表单维持舒适行高。 |
| 学习档案 / 知识库 | 以日期、标题、项目和内容摘要组织记录；文件类型与状态标签使用统一蓝灰色系。上传反馈和空状态清楚，但不占据主要视区。 |
| AI Assistant | 会话列表较窄、正文占主空间；模型/在线状态固定在工具栏，输入框固定在聊天底部。工具执行、待确认、失败和完成用独立状态文字呈现，与普通回答分开。 |

## 交互与动效

- 交互控件的悬停和按下反馈控制在 120–180 ms；页面内容进入 180–240 ms，位移不超过 8 px；抽屉和弹窗 220–280 ms。统一使用 `cubic-bezier(.2,.8,.2,1)`。
- 常规任务行悬停只改变背景、边线或最多平移 2 px；卡片不做大幅漂浮。完成任务时先即时显示勾选，再平滑更新计数和归档位置，避免列表突然跳动。
- 日历拖动、日期切换、AI 工具执行的动画只用来解释状态变化；等待状态要有稳定的文字提示。避免无限脉冲和连续呼吸效果干扰阅读。
- 动画尽量只修改 `opacity` 和 `transform`；进度条宽度变化可使用短过渡。所有交互保留键盘焦点轮廓，`prefers-reduced-motion: reduce` 时禁用非必要动画。
- 主按钮、链接、任务复选框和破坏性动作都要有可区分的 hover、focus、disabled 状态；小图标按钮可点击区域至少 40 × 40 px。

## 响应式验收

- **≥ 1200 px**：保留完整侧栏；Today 主列约占 2/3，右列约占 1/3；时间轴和进度在首屏内能扫读。
- **701–1199 px**：收窄侧栏或采用现有导航折叠方案；Today 两列按可用宽度收缩，统计卡由 4 列变 2 列；日历工具栏允许换行。
- **≤ 700 px**：导航抽屉、Today 单列（下一项任务与今日待办在日程细节之前）；任务元信息自然换行；弹窗、AI 输入区和日历不得横向溢出。周/日视图可在网格内横向滚动，但不能让整页横向滚动。
- 检查宽度 1440、1024、390 px；键盘焦点、减少动态效果、空数据、长中文标题、错误状态和高任务密度都要可用。
